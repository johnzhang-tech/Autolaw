1. Identify the Task
Modify an existing system where both admin and normal users currently share the same data view. After modification:

Admin users: Should see all data from all users.
Normal users: Should see only their own data.
Additionally, create an admin-only view that lists all users in the system.
2. Outline Requirements
The system must identify the current user role (admin or normal).
Data queries must be filtered based on the user role:
Admin: no filter or filter includes all users.
Normal user: filter to only their own user data.
Implement a new page/view accessible only by admin users that shows a list of all users in the system.
Enforce access control so that normal users cannot access the admin-only user list view.
Consider backend and frontend adjustments:
Backend: Modify API endpoints or database queries accordingly.
Frontend: Conditionally render components or pages based on user role.
3. Input/Output Specifications
Input:
Current logged-in user info, including:
User ID
User role (e.g., "admin" or "normal")
Output:
For data views:
Admin sees the full dataset (possibly an array of all users’ data).
Normal user sees only their own data subset.
For admin-only users list view:
Admin sees an array/list of all users with their relevant details (e.g., usernames, emails, roles).
Normal users get an access denied message or are redirected if they attempt to access this view.
4. Reasoning and Logic
User Role Detection:
Use authenticated user session/token info to detect role.
Adjusting Data Queries:
In data fetching function/method, check user role.
If admin, query all data.
If normal, query data filtered by user_id = current_user.id.
Admin-Only View:
Route or component should check if user is admin.
If true, fetch and display list of all users.
If false, redirect or render “Access Denied.”
Security:
Ensure backend API endpoints enforce role-based access.
Do not rely solely on frontend role checks.
User Experience:
On the normal user view, ensure the user sees only their data seamlessly.
For admins, provide clear navigation to their new “All Users” list.
5. Testing
Test admin user:
Login as admin.
Confirm they see all data on the main data view.
Confirm they can access the “all users” list view and see all users.
Test normal user:
Login as normal user.
Confirm they see only their own data.
Confirm they cannot access the "all users" list view (should redirect or show error).
Edge Cases:
No data for the normal user (empty data).
Admin user with no other users in the system.
Invalid access attempts to the admin-only view.
Security:
Try accessing admin-only data endpoints without admin rights (e.g., with modified tokens).
